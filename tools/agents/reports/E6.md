## Dúvidas e incoerências

1. **Divergência de semântica no ex. 7 (P8).** O C do README (`:647`) contabiliza `wins` no fim natural do worker. Isso contradiz o texto do README (`:668-670`), o backend §5.9 item 9 (`keel-c-backend.md:1386`) e o golden `012`. Corrigir o README (ou o contrário) é decisão para o André, porque é o texto normativo e a documentação pública que estão em jogo.
2. **A meta "bloco C é trecho literal do `expected/`" conflita com a ressalva do README.** `README.md:211` diz que o C dos exemplos usa "representações locais", e que "os nomes internos exatos, o mapeamento de linhas e as verificações de debug pertencem ao backend". Por isso ele não é literal hoje. Há duas saídas: (a) tornar os blocos literais e reescrever o que está acima, ou (b) manter a ressalva e fazer a conferência por script só para os blocos marcados. Qual das duas é decisão do André.
3. **O golden não tem `i16` nem buffer de `u32`.** Os exemplos 3, 4, 6 e 7 usam `i16`/`u32`, e o golden só usa `i32`/`size_t`. Para o literal ser possível, ou o README troca os tipos, ou entra um caso novo. Também é decisão do André.
4. **Duas formas do mesmo verbo no README.** O snippet `parallel search ANY` (`:113-121`) escreve `slice i32 part : xs` e `set(where, …)`. O ex. 7 (`:620`) escreve `slice.slice i32 part : xs`, e o `bs.k` escreve `buffer.set`. Não sei qual é a forma vigente, e não decidi.
5. **Afirmações sem caso.** O ex. 5 diz que `manual()` devolve 2, e o ex. 6 diz que os contadores terminam em `*a == 4` e `*b == 2`. Nenhum `expected/` ou `NOTES` tem isso. Não abri os `proof.c` dos casos `009` e `010`. Se eles afirmam esses valores, a afirmação está coberta pelo arnês, não pela saída.
6. **Pares 1 e 3 são o mesmo programa.** O bloco sem rótulo (7-27) e o ex. 2 (253-277) têm o mesmo corpo, e só diferem nos rótulos. Vale decidir se o README mantém os dois.
7. **Contagem de casos desatualizada.** O README diz 25 casos (linhas 34 e 687); o `golden/cases/` tem 26.
